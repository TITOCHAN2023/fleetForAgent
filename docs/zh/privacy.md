# 隐私与数据留存

本文描述仓库中的 Cloudflare Worker 实现。自托管者可以修改代码、配置和基础设施日志，也可能另做备份。这里没有把代码说明当作对生产配置的独立审计。

## 中枢能看到什么

中枢负责账号认证和设备在线目录，能够看到经过它转发的命令输入输出、插件消息和 Room 对话。HTTPS/WSS 保护传输链路，中枢本身仍在信任范围内。direct-only 文件传输的文件内容在端点之间传输，信令和状态依然经过中枢。

## Worker 保存哪些数据

| 数据 | 应用层规则 |
|---|---|
| 已完成的命令和插件结果 | 15 分钟过期 |
| 终端屏幕快照 | 5 分钟过期，活动会续期 |
| 活动执行与会话记录 | 24 小时过期 |
| 账号、凭据和设备信息 | 独立的持久记录，不随短期结果一起删除 |
| OAuth 待完成尝试 | 10 分钟过期 |
| 登录会话 | 空闲 7 天，最长 30 天 |
| Room 对话与任务记录 | 保存在 leader 机器，不写入 Hub 持久存储 |

过期时间用于应用读取检查和定时清理。定时器调度、旧记录清理与存储服务的行为，都意味着不能承诺到点立即物理擦除。重置 Token 会撤销访问，不会清空所有账号和设备数据，也不会撤销已经完成的命令。

设备缓冲、插件文件和 Room leader 的 SQLite 有各自的保存方式。AI 适配器与模型服务商可能保留自己的记录。Room 成员使用 Linux tmpfs，无法限制任意适配器写其他路径，也不能防止系统交换到磁盘。不能据此承诺全系统零留存。

## 连接前需要知道

先使用 `ask`。切换到 `allow` 后，命令和插件会以服务所在系统用户的权限执行，无需第二次确认。Fleet Sandbox 是产品名称，不代表操作系统隔离。敏感或不可信任务适合放在独立的低权限账号或虚拟机。

不要把 Token 放进截图、公开问题或 shell 历史。只把凭据交给可信的 MCP 客户端和运行器。网页使用登录 Cookie，并在本地保存主题与语言偏好。生成的 Token 明文只展示一次，无法从保存的哈希恢复。

公共 Hub 的运维管理员可以查看运维信息和封禁账号，没有专用的跨账号机器控制凭据。部署代码与基础设施仍由 Hub 运营者掌握。

数据处理问题可以在项目的公开 Issue 中询问，但不要包含私人数据。安全问题按 [SECURITY.md](../../SECURITY.md)报告。
