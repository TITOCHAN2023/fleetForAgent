# 运行时边界与剩余成本

本次限制的是临时输出，不是认证、路由归属或防重放凭据。缓存淘汰和断流不重发命令、不取消运行任务，不调整心跳周期，也不删除 Agent 操作回执。

| 组件 | 默认边界 | 超限行为 |
| --- | --- | --- |
| Worker/Node 经典 MCP SSE | 每条连接 8 MiB 编码字节队列 | 错误断流、丢弃队列并清理定时器/会话；任务继续。恢复时查询原 handle，不因断流重做操作。 |
| Node 结果 payload | 32 MiB、4,096 条、最后写入后 15 分钟 | 淘汰最早写入项；读取不续期。 |
| Node 屏幕 payload | 32 MiB、4,096 条、最后写入后 5 分钟 | 显式 corr 缺失时返回空，绝不回退别的任务屏幕。 |
| Node 终态摘要 | 4 MiB、16,384 条、24 小时 | 输出不在时返回 `status: unknown` / `RESULT_NOT_RETAINED`，不伪造成功。 |
| Worker 结果等待 | 每 corr 共享读循环，1 秒兜底，保持最多 30 秒 | 结果持久化后立即唤醒全部等待者；等待模块没有命令下发入口。 |

上述预算按编码后的 key/value 字节计，不等于精确 RSS。JS 字符串、索引等有额外开销。缓存读写时清过期项；完全空闲时，已过期 payload 可在预算内保留至下一次访问。

## 恢复与安全边界

结果淘汰后的 `get_result` 仅使用原 corr/fingerprint 查询 Agent。提供正数 `wait_ms` 会等待重新取回输出，超时仍保留明确的输出不可用说明。能否恢复由 Agent 的操作回执和输出保留状态决定，Hub 不重新下发 run。插件输出不能通过重新执行插件恢复，过期结果只报告 unknown。

独立 Node Hub 不淘汰既有 owner/live/alive 身份记录，因此摘要过期后仍可判断某个 handle 已结束。网站 Node runtime 为同样目的保留紧凑的已完成 device/handle 集合。这些无输出身份记录在重启前仍随历史任务数 **O(J)** 增长。本次只限制大 payload 缓存，不能声称整个进程内存恒定；安全回收身份记录需要单独的兼容性设计。未知 handle 和正在运行的任务不能被推断为已完成。

Worker 等待通知只存在于 DO 实例内，持久化结果仍是依据，初始化和兜底都会重读。超时或可用的内部 abort signal 会移除等待者；本次不把外部客户端取消信号新增透传到命令下发。客户端断开后内部等待可能保留到原有的 30 秒上限，但不能因此中止或重放任务。

## 其余修复与未做范围

Agent 对实时单行文本设置 64 KiB 上限并标识截断，不终止任务。dirty pane 选择改为公平轮转，但仍是 O(P) 扫描，不是 O(1) 调度器。Room SQLite 前缀查询改用索引范围；更广泛的任务分页下推和 assignee 索引本轮未做。设备别名 miss 使用迁移完成标记避免重复扫描；设置别名仍为 O(D) 账号内兼容性检查。

超量输出与慢消费者的边界行为有意改变，不能声称无限输出逐字不变。权限、防重放、插件执行和 WS/RTC 执行语义不与 payload 回收混为一谈。测试使用小预算、假时钟、本地模拟设备及隔离环境，不需要危险命令或生产机器。
